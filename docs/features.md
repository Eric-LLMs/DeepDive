# ✨ Key Features

## 🖥️ Desktop Workbench (Local Client)
- **Workspace file tree**: open any local folder as your workspace (the last one is restored on the next launch); add files from anywhere, create folders and text files, delete files & folders with a right-click (permanent, workspace-bounded), and fuzzy-search the tree with live suggestions that jump straight to a match.
- **Cloud Drive in the app**: the sidebar's **☁️ Cloud** source is a full cloud-file manager aligned with the web console — a tree (**My Drive**, every **workspace**, and **🗑 Trash**) plus a main-area **list / grid** toggle with a five-column table (`Name | Size | RAG Status | Query Repo | Updated`), per-folder **search**, **✏ Edit** mode with a **batch bar** (Download / Open / Share / Rename / Move / Copy / Trash; Restore / Delete permanently / Empty Trash in the Trash), role-gated **⚙ Manage** (workspace members + activity logs), **⟳ Refresh** (re-pull files / folders / trash without leaving the view), New folder / New text / Upload, and a **Query Repo** status column (`✓ In Knowledge` / Importing / Processing with ETA / **＋ Import to Knowledge**). `.md`/`.txt`/code rows open in the built-in Markdown editor (**Edit / Preview** toggle, **Save** — synced straight back to the server; a Mermaid `mindmap` note previews as an SVG tree of nodes + edges); other files stream into the in-window viewer via a temp-cache download. Anything you save shows up in the web console on refresh. Background refreshes never disturb you: the tree and table re-render incrementally (keyed rows), so the sidebar doesn't flicker or oscillate and your scroll position stays pinned while rows update.
- **Summarize**: condense a document/video into a summary or key-point outline.
- **Generate slides, mind maps & summaries**: turn the current material — the open conversation, workspace files, or any Cloud Drive files (multiple files merge into one artifact) — into slide decks, mind maps, and summaries; generation runs in the background (Generate stays greyed while it runs; the tracker always terminates — a dead job can never lock it) and the artifact is saved to your Cloud Drive. Asking the chat for it works too: "**generate slides of this page**" is model-routed — the agent's trigger call surfaces the same confirmation dialog as the toolbar, which opens the exact same generate dialog (source prefilled from the open material, output-folder picker included) and runs the same background job; asking the chat to *summarize / explain / translate* what you're reading is answered inline instead of being routed to a generation tool.
- **Customize Slide Deck**: slides open a purpose-built dialog that exposes only business intent — **Format** (**Detailed Deck**, a comprehensive deck you can read on its own, or **Presenter Slides**, clean visual slides with key talking points), **language**, **length** (Short / Default), a **Sources** picker (checkbox list of your Drive documents grouped with their subtitle siblings, with Show all / new-content / Recent filters), an **Output folder** row pinned full-width on top, and a free-text **Describe the slide deck you want to create** box (audience, style, focus). The engine underneath stays invisible: it designs the whole deck in **one pass over the raw source text** — every slide tells a piece of a **visual story** (theme, process, key concepts, relationships, evidence, examples, the visual treatment each deserves, takeaway), grounded with **locators** (every fact carries a doc/page/line citation — and never invents numbers); extracted figures are offered as reuse candidates and land as **real figure slides** — the original image is embedded in the PDF and PPTX with the slide's cards as its side notes; a figure named for a layout that has no slot for it is canonized into a figure slide or fails the gates loudly, never silently dropped — and a local deterministic gate plus a bounded **single-slide patch** loop (a flagged slide is repaired in isolation — its siblings are never touched) stands between the model and **deterministic layout compilation** — so process content really renders as **flowcharts**, architectures as **tiered diagrams**, comparisons as **tables**, and number-backed claims as **charts**. The canonical output is a compiled **16:9 PDF** (`<name>_slides.pdf`), alongside editable `.md` / `.pptx` exports and the `deck.json` source of truth; a page that cannot fit its content fails the job loudly instead of silently shrinking text. The engine converges instead of thrashing: common model format slips (numbers quoted as strings, a prose field wrapped in an object, a locator echoed back as text like `"page: null, start_line: 2530"`, out-of-enum labels) are repaired **deterministically before validation** — semantics are never trimmed and an ambiguous citation is never guessed — and when a retry is still needed, the feedback tells the model the exact slot shape to fix (e.g. how to add a missing locator verbatim, or honestly relabel the claim) instead of re-echoing the raw error; long generations ride a streaming wire, so a provider's gateway time limit can no longer kill a big full-context pass. Every run records **honest per-node telemetry** (per stage — `D/synthesize` and its rerolls `D/reroll_i`, single-slide repairs `D/patch_{slide}`, plus the zero-LLM local stages with their measured wall seconds and the render leg's page accounting — cover counted apart from content slides, plus any layout degradations — LLM calls, real prompt/completion tokens, latency, rejects, repairs applied) in the job result — partial stats survive even a failed run — so you can see exactly where a deck spent time and tokens.
- **Edit the material**: modify the loaded document in place.
- **Clip & discuss**: select a passage in the viewer, clip it, and start a discussion with the AI tutor about that selection.
- **Chat knows what you're reading (viewer-aware context)**: while a file is open, a 👁 chip under the chat input shows what's in scope (`name · p.12` / `· 22:44`). For **documents** the server never guesses your intent from wording: the agent receives a trusted **Viewer Access Context** note (asset id + current page — resolved by geometry at send time from whichever page actually covers the middle of the viewport) and decides the scope itself via `read_document` — the current page, the pages/ranges you name ("page 2 and 5", "pages 2-5"), or the whole document; a page-scoped ask about a format with no page axis (docx / txt / …) is answered honestly, never with a full-document substitute. **Video** has no tool channel for media time, so its on-screen content is injected directly: the subtitles of the past 20 seconds around the playhead (never future cues), or the whole transcript when you clearly ask for the whole video (an honest "too large / transcript not verified" reply instead of a substitute answer when that isn't possible). Explicit actions always ride into the prompt on top of any question: "📌 加入对话" on selected text, the ✂ region picker on images/PDF pages, and the video **📌 Frame to Chat** capture (auto-paired with the subtitles at that moment) — these arrive as `[V1]`-style data blocks and answers about them cite those tags; clicking a citation jumps the viewer straight to that page / timestamp (same asset only, never under your feet). The ✕ chip detaches the viewport only — pinned selections always survive. Works for local files never uploaded to the cloud (current page / subtitle window), and retrieval behavior is unchanged: this is a separate reference channel beside RAG, not a search filter — [design: §23](architecture.md#23-viewer-context-provider--the-open-document-as-reference-context).
- **Bookmarks**: mark pages, sections, or words to revisit — jump back to any saved spot anytime.
- **Learning notes**: capture and organize your notes alongside the material as you study, ready when you review.
- **Sessions search**: search your chat history by content — matching snippets are highlighted in the results.
- **Capture & attach a region**: the chat input's 📷 button freezes the current window (`webContents.capturePage`), then you drag to select a region (double-click = whole frame) before it's uploaded as a real-MIME PNG to the `chat/temp/` cloud folder and staged as the pending attachment; the screenshot renders **inline as a thumbnail** in the chat bubble instead of a filename chip, and when sent to a vision-capable chat model it also reaches the model **inline** as the message's own picture (see **Image analysis** below). A screenshot is **temporary** — it lives in the `chat/temp/` scratch zone the user may empty at will, and deleting its message/session trashes it (recoverable, folder-agnostic — the delete keys off the message's `attach_asset_id`, not the folder) — **except** a Q&A pair imported into RAG, whose image is **copied to `RAG/images/`** (keeping the `chat/temp/` copy) and preserved with the corpus instead of deleted — [design: §18.2](architecture.md#182-chat-screenshot-pipeline).
- **Multi-format viewer**: video (with subtitles), audio, images, PDF (with annotations), and text/code. Word/Excel/PowerPoint (`.docx`/`.xlsx`/`.xls`/`.pptx`) preview **in-window** with pure-JS renderers — **mammoth** (Word), **SheetJS** (Excel), **JSZip** slide deck (PowerPoint) — no external apps required; older binary formats (`.doc`/`.ppt`) fall back to your OS default app. One-click video **screenshots** and **Generate PPT / Generate Book**. The document toolbar is **source-aware**: a file opened from Cloud Drive — including a Research task-preview PDF — offers **⬇ Download** (save a local copy) and never **⬆ Upload** (which would re-push the asset's own cloud bytes as a duplicate); local workspace files keep the on-demand **Upload**. A **✕** (or **Esc**) dismisses the current document back to the empty state.
- **Subtitles**: a sibling `.srt`/`.vtt`/`.lrc` is auto-detected, or pick one manually; enable/disable and style it (size, color, background, position), and your settings are remembered.
- **Streaming chat**: answers stream in with a collapsible **💭 thinking** panel; the status bar ticks out how long the current phase has been running (`⋯ Working… · 7s`) so a slow round-trip reads as progress, never as a hang, and keeps a live activity line even on turns that suppress thinking; intermediate step narration is folded into the status bar rather than leaking into the answer — you get **one reply per turn**. Answers are in your language: the assistant replies in the language of your latest message and paraphrases or translates any retrieved material it cites into that same language. Dock the chat to the bottom or side, or float it as a window. Messages render **Markdown + math** (`$...$` / `$$...$$` formulas via KaTeX), and every bubble has **Copy / Read / Delete / Edit / Import to Knowledge** actions — **Read** speaks the message aloud via streaming Kokoro TTS (with a stop button); **Edit** (on a user question) re-asks it, dropping that turn and everything after before streaming a fresh answer; **Import to Knowledge** writes the Q&A pair into the query repository and flips to **✓ Imported** once covered. Sessions can be **renamed** (click the title), **pinned** / imported / **deleted** from a header **⋯** menu — which also **Generates a Mind Map / Slides / Summary** of the conversation or of Cloud Drive files: a dialog picks the source (**this conversation** / **Cloud Drive files**, a checkbox picker that greys out oversized / unsupported files), the output folder, and an optional custom prompt and file name; a **Generate** toolbar above the input adds one-click entries. The async job runs in the background (the toolbar button becomes a steady ⏳ and the session row spins while it runs; Generate stays greyed until the job actually finishes), and the finished `<name>_<tool>` artifact (mind map `.mmd`; slides a compiled 16:9 `.pdf` + `.md` + `.pptx` + `deck.json`; summary `.md`) lands in the chosen folder — a **view output** link jumps straight to it — auto-suffixed on name collision. The input box is Gemini-style — a **＋ attach** button (pick a file, attach the open cloud asset, or capture a window screenshot), a multi-line textarea (Enter sends, Shift+Enter for a new line), and inline **🎤 / 🌊 / 📷** toggles — **🎤** records a clip and gets back a transcript via **mic → local FunASR/SenseVoice transcription** (`POST /stt`; the text lands in the box for review, never auto-sent), **🌊** (waveform) opens a hands-free **voice call** — one click enters a loop of *listen → auto-transcribe on end-of-speech → send → Kokoro reads the answer aloud → listen again*, talking over the read-aloud interrupts it, and a second click hangs up — **📷** (right of the waveform) freezes the window for a **drag-to-select region screenshot** that stages as the pending message attachment (**Capture & attach a region** above); attachments ride on the next send.
- **Research tab & task monitor**: a **Research** tab joins the sidebar, and the chat header gains a **＋ Research** button (creating a task from the chat). Opening the Research tab with no task selected gives you a clean **blank chat** (deleting the selected task drops back to it) — turns there are **throwaway**: the session is marked ephemeral and never shows up in the Sessions list. The sidebar holds the task list — stage/status/live **RUNNING** badge, 🗑 delete that confirms first and surfaces a 409's reason verbatim — above a slimmed **status pane** (name/status, stage nodes, gates, any terminal `last_block` banner, and — once a task reaches EVIDENCE — a compact **Evidence graph** card: counts of sources `verified`, claims, and evidence verdicts `↑ supports · ↓ contradicts`, whose **View graph** button slides a **right-edge drawer** with the full source list and the claim→evidence mapping — excerpts, fetched URLs, verification badges — live-refreshing as the worker lands new rows and auto-closing when a new edition resets the graph). Selecting a task opens its **two-zone workbench**: a working-directory tree (`materials/` / `outputs/` / `task_spec.json` / `session_history.json` — VS Code-style dotted indent guides, folder/file rows with sizes and RAG tags, a title row with ACTIVE / Stage badges) beside a **file preview column** that persists across refreshes and live-updates when the agent rewrites the open file — a **✕** in its header dismisses an open temp-directory file back to the placeholder — with the **Activity** feed pinned as a collapsible bottom bar. The workbench stays in sync through a **live SSE monitor** per task (revision hints → coalesced refetch). Card actions: green **▶ Run** (click-to-run: opens the session and sends the run instruction), **⏹ Stop** while a run is in flight (cooperative cancel), and **🗑 Delete** — all disabled while a run is active, re-enabled only once the worker chain really ends. A run parked on an un-clearable gate shows **Approve / Reject** buttons in the task's chat. The chat header is **two-layer**: a top control bar (session actions + window controls; **New chat** now lives in the sidebar's Chats list) and, only in a research session, a full-width **research context bar** (`🔬 Research · <task title> · [stage]`); the **Chats** tab itself fills the whole pane with a fixed 4-row composer.
- **Native menus & settings**: everything you'd expect — open/switch workspaces, zoom & font size, fullscreen, Help & Feedback, About. ⚙️ Settings covers theme, display, updates, help, and about.

## 💬 AI Chat Assistant
- **Agentic Kernel** (`AgentKernel`): a composition root wiring a cache-boundary prompt assembler, deferred tool loading, dual-track memory, a skill catalog, and a read-only sandbox around a `ReactLoopAgent` step loop.
- **Cache-Boundary Prompt**: the system prompt is partitioned into three zones — a byte-stable static prefix (`apps/api/soul.md` persona + compact tool/skill catalog, shipped with the code), project context, and a per-step dynamic suffix — so the provider's prefix cache reuses the stable head across steps. Project conventions are loaded from the workspace's `DELVETA.md` into their own stable zone; `snapshot_key()` makes the cache identity measurable.
- **Deferred Tool Loading**: the prompt carries only a compact `name + blurb` catalog plus the resident `tool_search` meta-tool; matched tools appear in the visible set as stable `name + description` stubs (defer_loading style) so the cached tools array never churns, and each tool's full schema is returned in the `tool_search` result. The prompt window is also bounded by a per-message snip plus an in-run character-budget window guard that trims oldest-first between steps. **The catalog is never truncated**: if the full tool + skill index would overflow its hard capacity, the agent refuses to start rather than silently hiding a tool from the model.
- **Dual-Track Memory**: session recall fuses PostgreSQL tsvector (keyword) + pgvector (semantic) via RRF, recency-weighted so newer messages win near-ties; when the embedding service is offline it degrades to tsvector-only — never a silent empty. `memory_search` / `memory_save` are tools; `memory_save` writes guardrailed notes (kebab-case key, length-capped content, closed type taxonomy) to the local memory directory while the session stays read-only. Proactive recall injects top hits for your question into the prompt. Long conversations are auto-compacted into a **single structured session summary** (five sections: intent, decisions, key facts, files touched, open questions): the app carries its own live context — summary plus recent turns — so ordinary turns never re-load history from the server, and each fold is a one-pass rebuild from the full raw transcript, never a summary-of-summary, so nothing degrades with age — [design: §22](architecture.md#22-chat-session-memory-v2--client-live-state-authority--zero-read-turns).
- **Durable session continuity**: an edit or delete you make in the chat is what the next answer sees immediately — no wait for a server round-trip; after a restart or disconnect the conversation window rebuilds itself (compacted summary included) and a quiet reconciliation aligns the server to what you see. When a conversation compaction can't complete safely it is **deferred, never truncated** — you keep the full context and the fold retries on the next turn.
- **Skill Catalog**: skills (SKILL.md) are advertised as a complete one-line index — every skill, never capped or truncated; the full instructions are lazy-loaded through the `skill` meta-tool. Each skill's `allowed_tools` is hard-enforced by a `SkillScopeEnforcer` guard: once a skill activates, every tool call must land inside the union of the active skills' declared `allowed_tools` plus a small core meta-tool set — a tool outside that scope is denied with a "skill scope" message. Skills that declare no allowlist impose no restriction, and an unknown skill name fails **closed** to the core set.
- **Keyless web search out of the box**: `web_search` needs **no API key** — the default provider (`aggregate`) runs Bing, Google, and Baidu **concurrently**, each tolerant of being blocked (a blocked engine contributes nothing, the survivors still return results). Wrapped redirect URLs are decoded back to their real addresses, and results are deduped/fused across engines into one clean list; when the primary engines all come back empty, a slower DuckDuckGo engine is added as a second chance so a search never silently returns nothing.
- **Social search that degrades instead of failing**: the `search_social` adapters for **x** and **zhihu** no longer error out when no platform API key or login is configured — they degrade to a **site-scoped keyless web search** (`site:x.com` + `site:twitter.com` / `site:zhihu.com`), host-filtered, deduped, and quality-filtered, so community discussion stays reachable through the engines that index it. reddit keeps its OAuth-first path.
- **Read-Only Sandbox**: every tool call is gated by session permissions (READ / WRITE / NETWORK); file tools are rooted at the workspace dir and path escape is rejected. Writes and network access need an explicit grant or human approval. The `bash` tool runs behind a sandbox backend — **Docker by default** (one-shot container, workspace mounted read-write, network disabled by default, resource-capped) or a host sandbox (explicit opt-in for local development only, not a security boundary).
- **Cooperative turn stop**: a tool can end the *current* agent turn at the step boundary through the generic `AgentTurn.request_stop(reason)` contract — the loop honours it only after the step's tool results are committed, treats the reason as opaque, and stays free of any domain concept; the request is first-wins idempotent and honoured on both the sync and streaming paths, with a `turn-stop-requested` audit event recording the reason (Research uses it so a committed stage transition ends the turn instead of letting the model redo the finished stage's work).
- **Turn-scoped final answer**: the loop's answer fallback only ever scans messages created *this* turn — it pins the turn's user-message entry and stops the scan there — so a turn that burns its step budget on tool calls with no final text can never replay a previous turn's answer. An unanswered turn is reported honestly ("step budget exhausted; retry"), on both the sync and streaming paths — [design: §5.2](architecture.md#52-agent-loop--reactloopagent).
- **Reliable LLM calls & per-turn budget**: every model call goes through a timeout/retry guard — a hard 90 s timeout (streams bound only the first token), exponential-backoff retries for transient errors only (timeout / 429 / 5xx), and an error taxonomy that never swallows cancellation; an SSE disconnect aborts the request at once and the turn closes cleanly. Each turn accumulates usage and is priced against `max_budget_usd` — accounting is per-turn, so concurrent turns never share it. The **price source is the model catalog**: the resolved channel's per-1k pair is injected into the turn and priced with the same Decimal math as wallet billing; a model no price resolves yields **PRICING_UNKNOWN**, reported honestly as "unknown" — never disguised as $0 — and the budget check fails open, leaving the step cap and stall detection as fallback brakes.
- **Human-in-the-loop approvals**: a tool gated to **ASK** routes through a process-global approval bridge that emits an `approval-request` SSE event and blocks on your decision (`POST /approvals/{id}`; timeout → deny). In the desktop chat the request renders as an **inline decision card** in the conversation — **Continue / Cancel** with a live countdown mirroring the server's auto-deny — instead of a focus-stealing modal, and the decision can carry a feedback message that rides to the agent (on cancel it replaces the generic denial reason); every platform-written feedback (confirm / cancel / generation takeover) is worded as a **this-turn-only** instruction, so declining one tool call can never harden into a standing "stop calling tools" that silences later turns. In multi-node setups approvals resolve over Redis Pub/Sub; with no approver bound the tool is denied — safe by default.
- **Plan mode, subagents & checkpoints**: the `plan` meta-tool streams an explicit step breakdown before acting; `run_subagent` spawns a bounded child turn (empty history, filtered tool set, depth/step-capped) that returns its final answer as the tool result; before each turn the workspace is snapshotted into an out-of-tree shadow git repo, so `revert_to_checkpoint` can roll back a bad batch of agent edits.
- **RAG Retrieval**: a config-driven node pipeline — query rewrite → multi-recall (vector + keyword) → RRF fusion → rerank, extensible with CJK segmentation, contextual enrichment, parent/child indexing, and domain filtering. Full feature walk-through in **RAG & Query Repository** below.
- **Query Repository**: one search corpus for cloud-drive files (PDF tables transcribed via vision), Learning-Platform sentences/articles, and chat Q&A.
- **Attached screenshots reach the model two ways — inline first, tool as fallback**: when the chat model is vision-capable, an attached screenshot rides **inside the current message** as a real picture (multimodal image part), so the model literally sees *this* image and locks its answer to it — each new screenshot is judged on its own pixels, never on what an earlier turn's image or document said; oversized images and text-only chat models fall back to reading by `asset_id` (saved on the cloud drive) through the `vision` tool at the model's discretion — vision and RAG retrieval are both tools, so the LLM decides which to call and in what order; the image models are exactly the ones the user's role is authorized for (vision-marked names tried first, the role's other models as a fallback; guests and model-less roles ride the daily free allowance, over the limit → upgrade prompt; when nothing can see the image it says so honestly), and chat renders a retrieved image inline in the bubble; every image attach note — inline or tool — declares the attached image is **new** and that earlier image analyses in the conversation describe a different file, so a fresh screenshot is always re-read instead of a stale one recited — [design: §18.5](architecture.md#185-vision-routing).
- **Attached documents become readable content** (`read_document`): attach a **PDF / Word (.doc/.docx) / Excel (.xlsx) / PowerPoint (.pptx·.potx·.ppsx with speaker notes) / txt·md·csv·json / subtitle** file in chat and the agent extracts its text through the *same* ingest extractor (PyMuPDF body + vision-transcribed tables, python-docx, **antiword** for legacy `.doc`, openpyxl, python-pptx) instead of apologizing about parse failure; the tool also reads **page-scoped** — a `pages` spec like `"3"`, `"2,5"`, `"1-3"` (1-based, deduped, ≤16 pages per call) extracts only the requested PDF pages or PPTX slides, an out-of-range page fails the whole call **before** any extraction, formats with no page axis (docx/txt/csv/…) refuse page-scoped reads instead of substituting the whole document, the merged output is truncated once at 20k chars, and **asset ownership is verified before any bytes are read**; images are routed to `vision`, the attach note names the right tool per type, a legacy `.doc` additionally has its **inline pictures recovered and saved as drive images whose `asset_id`s are appended for the `vision` tool** — old-Word figures and picture-tables become readable instead of a bare `[pic]` placeholder; `.xls`/`.ppt` are refused with a resave hint (and a refused read explicitly forbids summarizing an earlier document in its place), and a huge document is capped with an honest truncation tail; the persona then splits the request by intent — questions *about the attachment* are answered from the extracted content only (no web search blending external material in), while attachment-*anchored* asks may search after extracting, with attachment vs external claims labeled — [design: §18.6](architecture.md#186-attached-document-extraction-read_document).
- **Fast-path control plane**: not every turn needs a ReAct loop. Before the Agent runs, a pure control plane resolves the turn to exactly one execution plan — plain conversation answers directly (DIRECT), an injected viewer selection is read straight from the screen (VIEWER), a pure private-corpus question runs retrieval without tool ping-pong (LOCAL_RAG), a fully-specified operation dispatches its registered tool exactly once with a deterministic confirmation (ACTION), and a grounded-read-plus-task chain runs as a fixed two-step COMPOSITE. Every fast path only takes turns it can certify; anything uncertain, mixed-demand, or mid-flight-failing falls back to the full Agent with your text **byte-identical** and zero trace, and every tool the fast paths run goes through the *same* permission waterfall (approval, sandbox, source fencing) the Agent uses — one execution authority, never a bypass. Failures are classified: incomplete user input escalates to the Agent to clarify with you; a system inconsistency, a governance denial (approval refused, policy fence, stale routing registry), or a mid-write failure terminate honestly with a plain message and **no automatic retry** — the Agent is never a recovery channel that could duplicate a side effect. Each path rides its own switch, all default-off (dark launch); with the gates closed the plane is behavior-identical to the Agent — [design: §24](architecture.md#24-chat-control-plane--plan-resolution-fast-paths--qir-intent-routing).
- **QIR — query intent routing (dark)**: an incremental routing stage inside plan resolution, not a second pipeline. When the lexical matcher abstains on an action request, a versioned, atomically published capability snapshot scores the sentence semantically and one bounded decision pass adjudicates among the top candidates — negation ("don't create a folder"), genuine ambiguity, and parameters that would need guessing all abstain by contract, and a model disagreement never invents a capability. Routing outputs only *which capability from which registry version*; argument binding reuses the existing extractors, and before dispatch the stamped registry version is revalidated against the live snapshot — a historical route never executes on blind trust. A published snapshot can be pulled (`unpublish`) at any time, after which routing abstains everywhere and every turn rides the Agent unchanged — [design: §24](architecture.md#24-chat-control-plane--plan-resolution-fast-paths--qir-intent-routing).
- **Intent Funnel (dark)**: the target routing chain beside the legacy QIR lane — a deterministic table **Matcher** over the published capability Registry, a vector **Recall** that only nominates candidates, one **ToolIntentModel** call that both selects the capability and drafts its arguments, and a **Binder** that only validates against the Registry's canonical parameter schema; every non-COMPLETE outcome (negation, low confidence, an off-card invention, a missing/dirty argument) hands the turn to the Agent with your text byte-identical. The local model adapter speaks **both wire formats a tool-tuned model actually emits** — native function-calls and the model's structured Markdown tool block — and normalizes them into the *same* internal verdict, so a correctly-formatted reply always reaches the tool instead of being mis-read as a refusal; ordinary prose, half-finished blocks and inconsistent tool names are still never treated as a call. Each hop rides its own switch (all default-off, per intent-kind gates OFF); with the gates closed nothing changes — [design: §25](architecture.md#25-chat-intent-funnel--nodeized-routing-toolintentmodel--shared-tool-runtime).
- **SSE Streaming**: Real-time token streaming to the frontend.

## 🔬 Research OS (Deep Research)
- **A persistent research workspace**: run a full multi-source investigation — plan, search, gather evidence, cross-verify claims, synthesize, and publish a cited report — inside a **Research OS project** (skill-driven) or **research task** (created from the chat). Every source, claim, and artifact is persisted, so the whole investigation is auditable and resumable — not a throwaway chat thread. — [design: architecture.md §17](architecture.md#17-research-os-module).
- **Chat-created research tasks with a cloud task folder**: the desktop chat's **＋ Research** button creates a task in one atomic request — a real **cloud task folder** in My Drive (under the folder you pick in a picker) containing `materials/` (copies of the selected cloud-drive assets, with a provenance record `{asset_id, name, cloud_asset_id, mime}` kept in the task state), `outputs/`, and `temp/` — all three work folders are created with the task, so the layout never arrives incomplete — plus live mirrors of `task_spec.json` / `session_history.json`. During a run each artifact's working copy mirrors into `temp/vN/`, and a **report** artifact additionally projects into `outputs/<task name>.md` (created on the run's first report write, updated in place within the run; a new run lands a new file). Server scratch state stays the authoritative copy of the task; the cloud folder is the user-visible projection. The brief is not decoration: the unattended pipeline loads `task_spec.json` into **every** generation node regardless of entry path — so ▶ Run with no chat in sight still honors an explicit instruction like 写一个中文报告 and delivers the paper in that language.
- **Task materials are first-class evidence sources**: `research_scrape` `action: "fetch_materials"` extracts **every file in the task's `materials/` folder in one server-side call** into the same per-run provenance ledger as web pages (`material://<cloud_asset_id>/<safe_name>` keys), so adjudication, `read` back, and claim edges treat your own documents exactly like fetched pages. Format is detected by **content, never file name**: **PDF** (text layer first; vision transcription only when tables are present and the text is degraded), **Excel** `.xlsx` / `.xlsm` (sheet/row caps, overlong sheets marked truncated), and plain text — `.txt` / `.md` / `.csv` / `.json` / `.log` (UTF-8 with GBK fallback). Not supported (refused with a clear reason, never silently skipped): `.docx`, `.pptx`, legacy `.xls` (resave as `.xlsx`). Per-file size is capped at 100k chars with a visible `[TRUNCATED]` flag; the whole folder stays under a 400k per-call budget via server-side paging — one call covers everything. A bad file lands in `skipped: [{name, reason}]` without breaking the batch; every material-backed source is **re-validated against the task's own materials folder** at read and commit time, so a borrowed `material://` URL can never inject an edge. — [design: architecture.md §17](architecture.md#17-research-os-module).
- **One task, one dedicated chat session**: each task binds a single chat session — a different kind than a normal chat (stored as `type=research` in the DB), hidden from the Sessions sidebar and deleted together with the task. Selecting a task silently opens its session (side-effect free); only typing a run instruction actually drives the task. Navigation never creates an execution.
- **Seven research tools, one workflow**: `research_project` (create / resume / snapshot / archive a project), `research_artifact` (write scratch, version, read / diff, one-call `review_draft`, and promote reports to the drive), `research_state` (advance through the stage DAG), `research_evidence` (record claim nodes and close a whole evidence chunk in one `adjudicate` call), `research_gate` (check stage gates and explain failures), `research_run` (record the synthesis execution), and `research_scrape` (save a raw search capture, **batch-fetch** a claim's real pages, extract the task's **materials** folder into the evidence chain, and read a fetched full draft back). They're mounted as a plugin, so the core agent kernel stays free of research-specific logic.
- **A 10-stage DAG with gates**: DISCOVER → FRAME → EVIDENCE → DESIGN → EXECUTE → EXPLAIN → WRITE → REVIEW → REPRODUCE → PUBLISH — the chain is always complete (no profile removes stages; under `literature`, DESIGN / EXPLAIN / REPRODUCE are light pass-throughs). Each stage advances only via `research_state transition_stage`, which reports one of **seven outcomes** (`ADVANCED` / `ALREADY_AT_TARGET` / `NOT_READY` / `GATE_BLOCKED` / `CONFLICT` / `ILLEGAL` / `ERROR`) and closes its compare-and-swap inside the persistence lock; a committed `ADVANCED` ends the current agent turn, so a finished stage's work is never re-done. `research_gate` checks that a stage's outputs exist before you move on — a failed gate explains why instead of silently proceeding.
- **Strict vs progressive — two gate pipelines, chosen at creation**: a task's `execution_mode` is picked when it's created (the ＋Research dialog offers both, defaulting to `progressive`; the API default is `progressive` too — the unattended auto-run is the code-driven pipeline, whose doctrine is degrade-honestly-and-advance, while `strict` remains selectable for gate-blocking control) and locked for its life. It never changes how a stage is worked — both modes run the same deterministic gate checks (read-only, never forging a verdict) — only what a **failed gate** does: `strict` blocks the transition until the work is actually fixed or a human **Approve** flips the gate to `OVERRIDE` — and on the unattended pipeline the blocking is fully mechanical: the transition fence evaluates an unchecked guard gate itself (0 LLM), requests the override on a FAIL, and **parks** the run on the Approve card instead of dying; approving resumes by advancing without replaying the finished node; `progressive` advances the stage anyway in the same atomic commit while recording the failed checks into the task's diagnostics (a `gate_diagnostic` event), so a run can finish to PUBLISH with honest gaps and a "Known gaps / unverified items" report (a failed gate in progressive mode is the honest diagnostic record, not "silently proceeding"). Gate checks carry a severity, and `QUALITY_GATE` reads the scorecard of record for **this edition**: the newest `scorecard.md` version tagged to the current run decides the verdict (the bar is ≥7 rows with zero fatal findings — `blocking`); a scorecard stamped to an older run or carrying no provenance at all is refused as a borrowed grade sheet (still `blocking`), and only a project with *no scorecard recorded anywhere* is tagged `diagnostic_only` — reachable only on legacy paths now, since the pipeline's REVIEW node renders `scorecard.md` mechanically from landed facts (0 LLM) for every edition. The artifact chain also has three hard stops: **CLAIM_GATE** requires the primary report to actually exist on disk before EVIDENCE closes — the primary binds to the run's first *report-named* write, and the pipeline's EXECUTE-stage notes are deliberately named `execution_notes.md` so only the WRITE paper can ever claim the binding (an execution log winning it was the hijack that shipped unreviewed drafts); a run can never settle as FINISHED while its primary report is unpromoted (the settle is refused and the run stops graded — no fake publish); and REVIEW / PUBLISH bind only the **current run's** tagged versions — a stale higher-numbered leftover from an earlier edition is a ghost that can't hijack the base or the promotion, and starting a new edition archives the previous report's version tree (`archive/run{N-1}/`, moved never deleted) so each edition's numbering starts clean. A progressive run that stalls or caps short of PUBLISH is deterministically **auto-settled** to a model-free `settle_report.md`; a strict run stops graded and waits on a human.
- **Claims as a graph**: each material claim is recorded as a `claim` node linked to its sources with `supports` / `contradicts` edges — contradictions are surfaced explicitly and the evidence trail is machine-checkable rather than buried in prose.
- **EVIDENCE closes a chunk in ONE `adjudicate` call**: the agent submits `research_evidence` `action: "adjudicate"` with the chunk's source URLs and pending claim ids, and everything else happens server-side inside that single call — every page is fetched through batched `fetch_save_batch` (≤5 URLs per internal fetch, SSRF-guarded, full page text saved into the run's `temp/vN/scrape/` with a per-run provenance row, already-fetched pages reused), ONE deterministic 900-char representative chunk per page is extracted by Python (never an LLM summary), relevance + verdict are judged in a **single streaming LLM pass** that replies with a minimal id-only payload (`{"results":[{"s","c","v"}]}` — short transport ids mapped back to real URLs/claims before anything is stored; hidden reasoning disabled for this id-only call; extra passes added only if the token budget overflows), and **all verdicts commit in ONE atomic `verify_batch` transaction** (evidence ids hashed from claim+URL, so re-runs upsert in place). The reply is a compact per-claim summary plus honest failure channels: `skipped_sources` (a 403/empty/interstitial page is terminal for the run, never a stall), `dropped_rows` (model-emitted invalid ids, server-rejected), `no_verdict_claims` (retry just that claim with better URLs). `verified` means *the run ledger fetched that page and the model judged the claim against the fetched text* — never the model's word alone; the WRITE stage may cite only pages the current run actually loaded. Per-leg timing telemetry (`fetch_ms` / `ttft_ms` / `stream_ms` / `parse_ms`) rides every call, and an ops switch (`RESEARCH_ADJ_DUMP=1`) dumps the full prompt + reply for offline auditing. Claims still enter the graph only as driver-recorded `claim` nodes with a canonical `strength` (`asserted / supported / confident / contested`; `high / medium / low` normalized on write, anything else refused with a repair hint).
- **REVIEW closes the whole stage in ONE `review_draft` call**: `research_artifact` `action: "review_draft"` (pass the report's `artifact_id`) feeds the **entire draft + claim graph** to one streaming LLM pass and receives back only correction instructions — `{"changes": [{"file","target","expected_old","change"}, …]}`, never prose, never a document echo. Python pre-checks every row under the **unique-match iron rule** (`target` occurs exactly once in the document; `expected_old` occurs exactly once inside the target's section), applies the accepted rows to an in-memory staging copy, and commits **all-or-nothing**: every row passes → one new version; any row fails → the staging copy is discarded, nothing is written, and the error names the exact failed rows so the fix is minimal. An empty `changes` list means the draft was fully supported. The review runs against the report version **tagged to the current run** (never a leftover from an earlier edition), and from REVIEW onward that reviewed v1 is **immutable** — corrections must land as new versions via `create_version` (an identical crash-rerun of an already-committed write stays harmless, and non-report artifacts are unaffected). The input is budget-bounded (`REVIEW_BUDGET_TOKENS`, default 200k) and a malformed reply gets exactly one repair attempt before aborting.
- **The `deep_research` skill — one-command entry point**: instead of driving the seven tools by hand, the agent activates the `deep_research` skill, which orchestrates the whole loop (clarify → plan → discover → frame → evidence → cross-verify → synthesize → write → review → publish). Its `allowed_tools` is scoped to the research tools plus search, so the workflow can't wander outside its lane. A `fact_check` skill covers lighter single-claim verification. A chat-created task's dedicated session auto-resumes this skill on the first typed message.
- **Server-owned, worker-driven runs to PUBLISH**: research runs belong to the server and no longer need a client attached. A run starts with a chat-handoff turn; once it ends, the API hands off to a **`research_drive` worker job** — one job = one deterministic pipeline stage node (bullet above); the auto-run never constructs the agent kernel — chaining nodes until the run reaches a terminal state, so one chat prompt can drive a task all the way to **PUBLISH** (under caps: 14 turns, 2 no-progress turns, 3 workflow retries, and a cost ceiling — the default **$0.40** is a **pre-call hard gate**: a turn is refused *before it starts* once spend reaches the cap, and every model call inside a node transits the stage's `llm_gate`, which checks the remaining budget before the request leaves the transport layer, so a run can never bill past the ceiling). A `RunState` driver parks the run in `idle / running / finished / blocked / stalled / cancelled / error` and records why it stopped in a terminal **`last_block`** banner. A task allows one live run at a time and **`is_running` stays on across the whole background chain**; a fresh chat-triggered run while one is active is a **409 conflict**. Runs survive crashes: task state is mutated through a cross-process **`portalocker` compare-and-swap** (monotonic `project_revision`, fsync-persisted), a stalled heartbeat is **re-run idempotently** on the same turn, and a stale run slot is adopted with its orphaned executions aborted — so deletion can't block forever.
- **Deterministic pipeline auto-run — code drives the flow, the model only decides**: each unattended turn runs the stage as a Python node — deterministic input prep (including the task's persisted creation-time brief, loaded on every entry path) → schema-locked structured decisions under a per-stage LLM quota (**REPRODUCE and PUBLISH are zero-LLM** hard gates; EXECUTE exactly two passes; WRITE is the only extended-reasoning stage; every other stage ≤ 2; DESIGN answers a fixed 8-field contract whose full text lands as a `Design` graph node) → **at most one repair** confined to format/schema breakage → append-only failure ledger → honest forced advance. Non-fatal defects degrade as recorded facts (a dead source channel costs one `source_unavailable` ledger line; an unfixed review lands `unreviewed` with the reason), never a laundered pass. A structural precondition violation (empty corpus, no usable draft, an unpromotable report) stops the chain **immediately as BLOCKED** — no re-run of the dead node, and merely *arriving* at PUBLISH is never finished: only the PUBLISH node's own promotion record is. The fetch channels (web / social / RAG / task materials) fan out concurrently with per-channel micro-timeouts, so one dead source costs a ledger line, not the run. — [design: architecture.md §20](architecture.md#20-research-execution-from-agent-driven-control-flow-to-a-deterministic-pipeline).
- **Per-task LLM trace for stall forensics**: every traced model call during a run — the Chat-path agent loop's full requests/responses (both step styles, success and fatal) and the REVIEW stage's internal reviewer passes — appends one JSON line (request, response or error, usage, duration, stage/run/turn tags) to the task's scratch `llm_trace.jsonl`, the evidence channel for post-hoc "why did this node stall or cost what it cost". Opt-in and observation-only: zero-cost when unbound, and a trace failure can never break the run.
- **One-click Run with live Activity, Stop, and gate approvals**: a task's card carries a green **▶ Run** button — clicking it opens the task's dedicated session and sends the run instruction in one action, so research starts in one click — and, while a run is in flight, a **⏹ Stop** button that **cooperatively cancels** (`POST …/cancel`; the current step finishes, never a mid-write kill). The desktop keeps the task in sync over a **live SSE monitor** (revision-change hints → one coalesced refetch) that **auto-reconnects** on drop and refetches immediately when Run starts, so Run/Delete/Stop disable while a run is active and re-enable only once the worker chain really ends (`research_continuing`). When a stage gate fails — hit by the interactive agent or evaluated mechanically at the unattended pipeline's fence — the run parks **BLOCKED** with an **Approve / Reject** card in the task's chat (`POST …/approvals/{id}`) — approve flips the gate to OVERRIDE and the run resumes without redoing the parked node, reject keeps it FAIL and asks the agent for another approach. An **Activity** bar streams what the research is doing right now (normalized tool steps, notices, turn-finished) and a terminal **`last_block`** banner explains why a stopped / blocked / stalled / finished run ended.
- **Publish closes the knowledge flywheel**: each run's promote mints a versioned final `temp/v{N}/<id>_v{N}.md` in the task folder — the reviewed Markdown is archived by edition as the *intermediate* publication artifact, no longer dropped into `outputs/` — and sets it **RAG-pending** (a re-promote inside the same run refreshes that one file in place; a later run writes a fresh `temp/v{N+1}/`, promoting only the current edition's own latest reviewed version). The Markdown promote remains the **sole publish authority** (the PUBLISH gate, the run settle, and the finished predicate all hinge on its `PROMOTED` + `drive_asset_id`); `outputs/` holds only the compiled publication PDF (next bullet). A skill-driven project without a cloud task folder still uploads to `research/<project_id>/`. The projection worker indexes the promoted Markdown, so the published report becomes retrievable through `rag_search` in later sessions.
- **Publication PDF — the Artifact Compiler (default-ON, deterministic)**: **unless a task opts out** with `pdf_report: false` (default-ON, applied to new *and* existing projects), the terminal PUBLISH node — after the Markdown gate has promoted the report — additionally compiles a **publication-grade PDF** with **zero LLM in the path**: the finalized manuscript is *projected* (typed verbatim, never rewritten) into a Document AST, typeset by the Typst engine, and the manuscript hash rides the run id so a re-publish of the same edition **replays the identical committed result**. The PDF lands in the task folder at `outputs/<task name>_v{N}.pdf` (N = the run's sequence number; the name is cleaned of emoji / special chars and its stem hard-capped at 64 chars) and as a Cloud Drive asset; a skill project with no cloud folder keeps the stable `report.pdf`. In-text citations (`[ev:…]` / `[src:…]` / source URLs) resolve back to the research graph through an identity map (evidence id == graph node id) and every run persists a reload-safe `provenance.json`. The compiler answers only with an **ArtifactRef** (ids and hashes, never host paths). Failure doctrine: publishing is **never** held hostage by the sibling — success records `pipeline.publish.pdf` (and clears any earlier error) while a PDF fault still promotes the Markdown and terminalizes an honest `FAILED_BLOCKED` compile run, surfacing the reason in **both** a ledger line **and** the persisted `pipeline.publish.pdf_error`. The Markdown gate's verdict is never bypassed, delayed, or revoked by the PDF. — [design: §21](architecture.md#21-research-artifact-compiler-publication-pdf), full spec [docs/research/19](research/19-pdf-artifact-compiler.md).
- **Cascade delete**: deleting a task confirms first, then moves the whole cloud task folder into the Trash, removes the task state, and deletes **every chat session ever bound to it** with it — the task↔session binding is the authority, not the session's kind flag — their messages and screenshots go too; restoring the Trash folder never resurrects the task. A task that is RUNNING, or whose report the Knowledge Base already indexed, refuses deletion with a **409** and keeps the task.

## 🔎 RAG & Query Repository
- **Plug-and-play retrieval pipeline**: the retrieval flow is a composable list of stages. Default chain:
  *query rewrite → vector recall + keyword recall → RRF fusion → cross-encoder rerank*, plus two optional
  stages — *parent-expand* (widen a leaf hit to its parent chunk) and *relevance check* (drop chunks the
  LLM judges irrelevant). From admin **RAG → Nodes** you add / remove / reorder / enable / disable any
  stage and edit its parameters live — no code, no restart — [design: architecture.md §10.6](architecture.md#106-nodes).
- **Three input channels, one searchable corpus**: cloud-drive files, Learning-Platform sentences &
  articles, and chat Q&A all feed a single query repository, so one query retrieves across all of them.
  Each entry is tagged by source; learning / chat content stays visible to the user who imported it,
  while files keep their usual sharing / ACL rules — [design: §10.8](architecture.md#108-query-repository-multi-source-import).
- **Built-in product manual, always retrievable**: a Delveta user manual (features, where things are,
  setup steps) ships with the server and is **boot-seeded into the corpus** (chunks + embeddings) as a
  fourth, always-public channel — visible to every tenant and to guests, and self-healing: a version
  marker re-seeds after a product update, and a failed seed just retries on the next boot. Ask the chat
  a "how do I use Delveta" question and the agent answers from the manual via `rag_search` instead of
  inventing UI steps.
- **Import content & multiple text formats**: files get a **＋ Import to Knowledge** button and an
  "in knowledge" badge once indexed. Supported formats: plain text (`.txt` / `.md` / `.log` / `.json` /
  `.csv`), subtitles (`.srt` / `.vtt` / `.lrc` — indexed as timestamped cue-grouped chunks, so answers
  cite `<video name> @ H:MM:SS`), Word (`.docx`, plus legacy `.doc` via **antiword** with UTF-8
  mapping — if antiword is missing the file is refused with a resave hint, never mojibake),
  PowerPoint (`.pptx` / `.potx` / `.ppsx` — per-slide
  text plus speaker notes, embedded pictures extracted with slide-number anchors), and PDF (`.pdf`). PDFs extract body text
  *and* detect tables, rendering each to an image the vision LLM transcribes (a failing table is skipped,
  never fatal). The Learning Platform lets you import saved sentences and write articles; chat lets you
  import a single reply (bound to its question) or organize a whole session — the LLM merges the same
  question's follow-up turns into one entry and splits distinct questions. Imported chat entries show a
  persistent **✓ Imported** state — [design: §10.8](architecture.md#108-query-repository-multi-source-import).
- **Document images join the RAG flow**: importing a PDF/DOCX/PPTX/DOC also extracts its embedded images (PDF pages via `pymupdf`, DOCX paragraphs via the OOXML relationship parts, PPTX slides via python-pptx picture shapes — keyed by slide number; legacy `.doc` has no manifest, so a **deterministic magic-header scan** recovers the inline rasters — PNG/JPEG/BMP verified by Pillow, WMF/EMF metafiles rendered where the platform allows — anchored to the paragraph whose `[pic]` placeholder they sit behind) and saves each to the cloud drive as a derived asset. During ingest each chunk is tagged with `meta.pages` + `meta.image_ids` (the **union** across every page/slide/paragraph the chunk spans — no dropped images on cross-page chunks); at retrieval the agent sees those ids and reads the actual images with the `vision` tool. On top of the references, **image captions are searchable**: the vision LLM describes each unique image once at ingest and the caption is stored as its own chunk (`meta.kind = "image_caption"`), so a text query can find a picture even before the agent opens it — [design: §18.3](architecture.md#183-rag-document-image-pipeline-extraction--meta-annotation).
- **Rate the sources behind an answer**: when a reply was grounded on `rag_search` hits, the assistant bubble shows a 👍/👎 panel over exactly those sources (with an optional reason); the verdict lands in the golden-set feedback table, and the hit snapshot persists with the message so the rating is still there when you reopen the chat.
- **Chat screenshots imported into RAG are preserved**: a chat Q&A whose question carried a screenshot writes that asset into the chunk's `meta.image_ids` on import (single-pair and whole-session imports alike), so retrieval returns it for the `vision` tool. The import **copies** the image into `RAG/images/` while **keeping the `chat/temp/` copy** — the two rows share one content-addressed blob, so clearing `chat/temp/` can't orphan a referenced image (and the copy costs nothing extra). A screenshot is temporary and dies with its chat — deleting the session/message still removes the `chat/temp/` copy — while the `RAG/images/` copy is a separate asset row that survives deletion, so the image stays stored alongside the RAG text — [design: §18.2](architecture.md#182-chat-screenshot-pipeline).
- **Configurable chunking**: pick a split strategy — `fixed` sliding window, `paragraph`, `sentence`, or
  `semantic` — and set chunk size / overlap. Optionally enable **contextual** enrichment (an LLM-written
  context prefix per chunk), **parent/child** indexing, **CJK** keyword search (jieba), and **image
  captions** (on by default — a vision-LLM description of each embedded document image becomes a
  searchable chunk; turn it off to skip the vision calls at ingest). All of it is
  driven from the admin console and applied on re-index; a **Chunking preview** tab shows exactly how a
  strategy splits your text before you commit — [design: §10.7](architecture.md#107-ingest-side-runtime-configured-chunking).
- **Parent/child (small-to-big), an input/output pair**: turn on parent/child **indexing** under chunking
  to store leaf chunks plus larger parent windows (retrieval searches the leaves), then add the
  **parent_expand** stage so a leaf hit returns its parent's fuller text. The admin **RAG → Repository**
  tab lists every imported non-file chunk with a source badge and per-chunk delete — [design: §10.6](architecture.md#106-nodes).
- **Test before you ship**: the admin RAG module has a **Test** tab that runs the configured pipeline
  stage by stage and shows a per-node trace, and a golden-set **Eval** regression that scores
  Recall@k / Precision@k / MRR against your expected answers — [design: §10.10](architecture.md#1010-admin-console).
- **Domain-scoped search**: the `rag_search` tool takes an optional `domain` argument — retrieval
  narrows to assets in that knowledge domain (file chunks only) — [design: §10.6](architecture.md#106-nodes).
- **Re-index & safe re-import**: an admin **Reindex** button re-ingests every ready file under the
  latest chunking config; re-importing a source replaces its old chunks first — no duplicates. Rebuilds
  are atomic per asset (old chunks replaced in one step), so a worker timeout preserves already-committed
  chunks; on completion the corpus version bumps, dropping stale cache hits immediately — [design: §10.12](architecture.md#1012-query-cache--retrieval-feedback).
- **Query cache**: repeated queries short-circuit through a Redis cache keyed on (query, filters,
  top_k, config version, corpus version) — a topology change or a re-index invalidates automatically.
  The cache is a pure accelerator: any failure falls through to the pipeline — [design: §10.12](architecture.md#1012-query-cache--retrieval-feedback).
- **Retrieval feedback loop**: a 👍/👎 rating for the chunks behind an answer is recorded via
  `POST /rag/feedback` — each entry snapshots the query, the retrieved hits, and an optional reason
  into `rag_feedback`, growing a golden dataset for eval and fine-tuning — [design: §10.12](architecture.md#1012-query-cache--retrieval-feedback).
  (The recording endpoint is live; the workbench UI that calls it is not wired up yet.)
- **Degrade, never break the chat**: when the retrieval stack is unavailable, the assistant answers
  from its own knowledge with a notice instead of erroring or retrying — [design: §10](architecture.md#10-rag-module-config-node-pipeline).

## 🤖 AI-Powered Interactive Study
- **Seamless Navigation**: Switch instantly between words using **"⬅️ Prev"** and **"Next ➡️"** buttons without closing the dialog.
- **Hybrid Search Engine**: Combines PostgreSQL full-text search (exact keyword) and pgvector (semantic). If an exact sentence isn't found, it finds the most semantically similar sentence (e.g. searching "GQA" finds sentences about "Group Query Attention").
- **Context-Aware Explanations**: Uses LLMs to translate sentences and explain *exactly* what a term means within that specific context.
- **Auto-Fetch Definitions**: If a term lacks a definition, the system automatically calls the LLM in the background to fetch a precise English definition and Chinese translation.
- **Visual Context for Professional Vocabulary**:
  - **Multi-Dimensional Image Search**: Grasp complex or abstract terms instantly. The system automatically scrapes Google Images (with Bing as a seamless fallback) using a combined 3-tier strategy: *Term alone*, *Term + Definition*, and *Term + Contextual Sentence*.
  - **Asynchronous Loading & Randomized Regeneration**: Images load via a non-blocking UI mechanism so you can study text while images fetch in the background. Click **Regenerate** to sample a new set from a broader candidate pool.
  - **Local Image Caching**: Once saved, images are downloaded to a local cache and linked via relative paths for zero-latency loads and offline availability.
- **Built-in Mic Widget**: Record your own voice directly in the browser and compare it with the generated TTS audio for pronunciation practice.
- **Audio & Pronunciation**: Generate high-quality TTS audio for words and full sentences on the fly, with local audio caching to save API costs and speed up loading.
- **Importance Rating**: Rate terms from 1 to 5 stars (⭐⭐⭐⭐⭐) to prioritize your learning.

## ☁️ Cloud Drive (Personal & Shared File Storage)
- **My Drive + shared workspaces**: every user gets a private **My Drive**, plus shared **workspaces** (owner / admin / editor / viewer roles) for team files. Files live in a **globally content-addressed object store**: every unique file maps to one physical blob keyed by **SHA-256**, deduplicated across all users and workspaces (ref-counted — the bytes are freed only when the last reference is purged).
- **Instant upload & resumable chunks**: uploading an already-stored file short-circuits to **instant upload** (no bytes transferred); large files stream in **8 MB chunks** (`upload_sessions` tracks received chunks) with a progress bar and safe re-upload.
- **Notes & Markdown editing**: text files (`.md`, `.txt`, code, data) open in an in-page **note editor** — an **Edit / Preview** toggle renders Markdown live, and **Save** (`Ctrl+S`) rewrites the file in place (the bytes are re-deduplicated and RAG indexing re-runs). Mermaid mind-map files (`.mmd`, or any note whose text starts with `mindmap`) preview as an **SVG tree diagram** — nodes and connecting edges — in both the desktop and web note editors. Rendering is XSS-safe: raw HTML is escaped and `javascript:`-style links are blocked.
- **In-window Office previews — web console and desktop**: both the **web console Cloud Drive** and the **desktop app** render Word/Excel/PowerPoint files in-window (`.docx`; `.xlsx`/`.xls`/`.csv`/`.tsv`; `.pptx`/`.ppsx`/`.potx`/… slide decks) with the same pure-JS renderers (**mammoth** for Word, **SheetJS** for spreadsheets — one tab per sheet — and a **JSZip**-based slide deck for PowerPoint). Clicking never downloads: only the **⬇ Download** button fetches the bytes. `.doc`/`.ppt` have no browser parser and show a **can't-preview** panel (Download / Open in new tab), while images, PDF, video, and audio open in a new tab.
- **Push files into the query repository**: text-bearing files (`.txt`/`.md`/`.pdf`/`.docx`/…; audio/video/slides excluded) show a **＋ Import to Knowledge** button — click it to ingest (or re-ingest under the latest RAG config), and an **In Knowledge** badge marks files already in the corpus.
- **Derived images with a linked lifecycle**: PDF/DOCX/PPTX/DOC embedded images are saved to `RAG 图片/<doc>/` as assets carrying a `source_asset_id` back to their source document and a content hash — re-importing the same document reuses existing images instead of duplicating them (a chat `read_document` of the same `.doc` lands on the very same assets), and deleting / permanently purging / restoring the source cascades to its derived images (with per-image object ref-counts so the blob store never leaks) — [design: §18.4](architecture.md#184-derived-image-lifecycle-delete--trash--purge--restore).
- **First-class folders**: multi-level folders (`folders` rows with full `/`-paths) live side by side with files, and the file manager tree combines them. Create/rename/move/delete folders; renaming or deleting a folder rewrites the path prefix of every file and sub-folder beneath it.
- **Context menu & collision-safe naming**: right-click a file or folder for **📄 New text file**, **📁 New folder**, **📤 Upload**, **⧉ Copy** / **⇄ Move to…** (files; folders move only — see *Copy & Move*), and **🗑 Delete** (deleting a folder trashes its files first). Files and folders share one namespace per directory, so creating/moving/renaming into a busy spot auto-suffixes `(1)`, `(2)`, … before the extension (`docs` → `docs(1)`, `a.docx` → `a(1).docx`) instead of failing.
- **Copy & Move**: right-click a file (or the whole edit-mode selection) — or use the batch bar's **⇄ Move** / **⧉ Copy** — to relocate or duplicate files into any **My Drive folder** via a tree-picker dialog (**Copy to…** / **Move to…**). **Copy** is pure-logical: it adds a new asset row pointing at the same content-addressed blob and bumps the object's **ref_count** (+1) — no bytes are re-uploaded, and deleting either row later releases exactly one reference. **Move** only rewrites the file's logical address (workspace / folder); folders move with their whole subtree (cycle-safe) but are never copied. Name conflicts are resolved **server-side** right before the write (auto-suffix, surfaced back as a toast), never by a client pre-check.
- **Fuzzy search with suggestions**: a client-side, case-insensitive fuzzy matcher (prefix > substring > folder-path > subsequence scoring) with a live suggestion dropdown; you can scope a search to a workspace or search all of My Drive.
- **Trash & retention**: deleting a file moves it to the trash — bytes are kept (no ref-count release) until you **Restore**, **Delete permanently**, or **Empty Trash**. Trash auto-purges entries older than **30 days** (lazy sweep on list). Deleting a workspace trashes all its files and moves assets to My Drive trash.
- **Sharing & permissions**: per-file ACLs — grant read/write to specific users or create a **public link** (shareable without an account). Visibility is computed with three channels (ownership, workspace membership, ACL) so owner/admin/editor/viewer each see exactly what they should.
- **Member management & audit**: workspace owners/admin add/edit/remove members and grant the `admin` role (**only the owner** can grant admin/owner); every mutation is recorded in an append-only **activity log** (workspace members can read it; admin/owner manage it).

## 👥 Multi-User, Roles & Billing
- **Admin console** (`/admin`): a self-contained single-file SPA with five modules — **Providers** (credentials + model catalog + routing weights), **Roles**, **Users**, **Tokens**, and **Tools config** (web-search provider, SMTP, free-form key/value tool params, test email). A default `admin`/`admin` credential is seeded into the DB on first boot; console login is stateless (a signed session token, never persisted), so it never pollutes the tokens table.
- **Per-role LLM channels**: every role binds the provider channels it may use (`role_credentials`); each login pins one random active channel to the token, and chat routes through it per-request with failover.
- **One dispatch gateway**: *every* LLM call platform-wide (chat, research, toolkit, worker jobs, retrieval) passes the same authorization funnel — no valid channel means a 503 at submit time or a fail-fast at worker job start, never a silent global-key fallback; workers hold no resident keys (see [architecture §12.6](architecture.md#126-llm-dispatch-gateway--one-funnel-shell-workers-job-level-fail-fast)).
- **Streaming batch transport**: structured batch calls (`complete` / `complete_json` — toolkit generation, deck passes, research nodes) stream and accumulate their response, so a provider's ~300 s non-streaming gateway cutoff can never kill a legitimate long generation; the per-call timeout bounds only the idle gap between chunks. Hidden reasoning is disabled on these calls (`LLM_DISABLE_THINKING`, default on) — reasoning tokens are pure latency when the output is schema-validated JSON — while interactive chat keeps its 💭 thinking, the one exception being **Viewer FOCUS turns** (on-screen Q&A over a small window — [§23](architecture.md#23-viewer-context-provider--the-open-document-as-reference-context)).
- **LLM key management**: Tokens → LLM Keys manages the per-user key-grant matrix — which user may use which provider key; keys are shown masked (`sk-***`) with one-click copy, and a user's access to a key can be revoked or restored independently of their login.
- **Self-service accounts**: users **register** themselves (username + email + password); an **email-verification** link gates the first sign-in, and **forgot-password** sends a one-time reset link. After signing in, users edit their profile (display name, username, contact email, phone, avatar) and change their password — all from the web and desktop clients. Admins can still create accounts directly.
- **Email & SMTP**: verification / reset mail is sent over SMTP configured in the admin **Tools config** page. When SMTP is not configured, the one-time link is returned to the client instead and shown inline (dev mode), so registration still works locally.
- **User accounts**: users (and the web/desktop console) log in to receive an opaque token. Roles (`regular` / `pro` / `vip` / `admin` / `anonymous`) carry per-role quota (daily/monthly requests, tokens, RPM, cost) and an optional default model.
- **Server-managed config**: LLM provider keys, the model catalog, and the admin credential live in PostgreSQL (`app_settings`) — not `.env` or repo files — and are edited from the admin console.
- **Pay-as-you-go billing**: per-model pricing (prompt/completion per 1k tokens), a cash wallet per user, and an append-only ledger with a `balance_after` snapshot. Usage is **free first** (within the role's daily/monthly/token quota); once the free quota is exhausted, overflow is charged to the wallet — a drained balance returns **402**. Every usage log records the **serving channel** too, so the admin can aggregate cost per provider key.
- **Guest access**: anonymous users can chat without an account, identified by a **signed server token** (a client-supplied id is never trusted) and capped per day (`guest_daily_limit`, default 10); exceeding the cap prompts them to sign in.
